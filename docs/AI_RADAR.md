# AI 信息雷达

## 审计结论

旧 digest.py 将发布时间早于 72 小时的内容直接排除，只取综合兴趣推荐池前 20 条；关键词命中数、热度和新鲜度决定排序。sent.json 90 天淘汰且输出即确认发送。没有独立候选池、已读状态、邮件发送器。旧 Skill 和 Cron 将“今天”与采集条件绑定。

## 目标与边界

MyBot 维护独立 SQLite AI 信息池；OpenBiliClaw 继续负责平台认证、搜索、热门、相关推荐、探索与兴趣画像。额外的 AI 主题轮换搜索不依赖个人画像，抓取后的所有内容先过 AI 相关性门槛。B 站搜索复用上游客户端，小红书复用上游有预算和冷却保护的任务生产器及 Edge 扩展。不修改上游画像、Cookie、模型配置；不调用社交写操作。

新闻/发布动态使用较快的新鲜度衰减；教程、项目、工具、经验、工作流衰减较慢，没有发布年龄硬过滤。发布时间与首次发现时间分开保存。评分公开拆分为 AI 相关性、实用价值线索、时效性、未知方向探索、个人兴趣（小权重）。启发式分数不是事实核验或全文质量保证。保留上游时间字段，不把时间未知误报为最新。

平台内容 ID / 规范 URL 去重，跨平台标题指纹去重；本地 bge-m3 向量只用于相似内容分组与单次交付多样性，不永久删除相似项目的更新。发送记录和明确已读记录长期保留；浏览器 hover/scroll/snapshot 不算看过。一次预览不产生已发送状态。

采集与交付解耦：collect 更新池，digest 从池预览，send-email 建立持久 outbox 后投递。SMTP 明确接受才写 sent；连接在 DATA 后结果不明确则进入 uncertain，不自动重发，避免邮件重复。需要发件账户 SMTP 授权码；收件地址不是发信凭据。

新增来源实现候选数据契约即可接入。现阶段只启用 bilibili/xiaohongshu。轮换主题覆盖模型/产品、工具、开源项目、编程、Agent、办公、创作、经验和冷门探索；采集失败不清空历史池，报告每条采集通道的状态。

## 实际实现约束

候选宽召回使用标题/简介关键词；DeepSeek 通过上游 LLMService 和费用记录器审核，
禁用历史 core memory 注入，AI 核心相关性须至少 0.65、元数据价值至少 0.4。
每轮最多审核 24 条，按最早待审核顺序，不按热度挤掉冷门作品。
签名缓存随标题/简介变化失效；模型失败或响应缺项时不把未审核内容交付。
不能把此审核误称为事实核验；只看标题/简介可能漏判营销或教程失效。

主动搜索每 6 小时一轮，每小时同步上游异步结果并消化审核积压。
12 组查询轮换，不受个人画像控制。推荐/热门/相关/探索是复用上游已生成的缓存成果，
MyBot 不重新实现这些推荐算法，也不承诺每轮强制执行全部上游发现方式。
上游 XHS 生产器保留任务预算、冷却和在途任务保护；浏览器离线时任务等待。

来源契约为 source_platform、content_id/bvid、content_url、title、description/body_text、
author_name、published_at、discovery_lane/discovery_query 和低权重 confidence。
未来来源适配器只需提供候选/已读事件，复用 MyBot 数据库及交付层；
当前没有启用 GitHub/X/Reddit 等新来源。

兼容保留的 Settings.max_age_hours、fetch_per_platform 仅供旧调用方/测试使用，
雷达采集不执行这些旧限制。历史 sent.json 继续读取，新的发送状态以 SQLite 为准。
邮件凭据尚需用户在本机配置，收件地址本身不授予 SMTP 发信能力。
